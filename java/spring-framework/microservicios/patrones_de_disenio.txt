Los patrones de diseño service registry y service discovery sirven para cuando hay muchísimos microservicios y es complicado recordar la URL que le corresponde a cada uno. Service registry es una fuente centralizada de información que elimina la necesidad de que tengamos que configurar manualmente las URLs o direcciones IP y puertos de los microservicios. Cuando un microservicio se quiere comunicar con otro, el primer microservicio le "pregunta" al service registry a donde está el microservicio con el que quiere comunicarse, a esto se le llama service Discovery. Service Discovery y service resitry son patrones de diseño complementarios. Gracias a estos patrones de diseño, nuestra aplicación se puede adaptar a cambios de infraestructura sin tener que cambiar el código de manera manual

El patrón de diseño balanceador de carga provee alta disponibilidad, ya que si un microservicio falla o se vuelve inaccesible, se redirigen las solicitudes a otras instancias disponibles. Los usuarios pueden seguir utilizando los servicios incluso si uno de ellos está experimentando problemas 

El patrón de diseño API Gateway ayuda a gestionar la autenticación y autorización de los clientes
