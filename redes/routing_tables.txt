¿Qué es una routing table?

Una routing table es un conjunto de reglas, generalmente vistas en formato de tabla, que se usan para determinar a donde los paquetes de datos que viajan por una red IP serán dirigidos. Esta tabla se almacena generalmente en la RAM de dispositivos de envío, como routers y switches de red
En redes de computadoras, cada routing table es única y funciona como un mapa de direcciones para redes. Almacena el origen e IP destino de los dispositivos de enrutamiento en la forma de prefijos junto con las direcciones de default gateway e información de enrutamiento correspondiente
Las routing tables típicamente se actualizan dinámicamente a través de protocolos de enrutamiento de red. Pero a veces los administradores de redes podrían añadir entradas estáticas de manera manual

--------------------------
¿Cómo funciona una routing table?

El propósito principal de una routing table es ayudar a los routers a concretar decisiones efectivas de enrutamiento
Cuando una paquete es enviado a través de un router para ser enviado a un anfitrión en otra red, el router consulta la routing table para encontrar la dirección IP del dispositivo destino y el mejor camino para alcanzarlo. El paquete es luego dirigido a un router vecino (o el próximo salto listado en la tabla) hasta que llegue al destino final
De acuerdo a AWS, para manejar el tráfico de red, un router consulta sus routing tables millones de veces cada segundo

-------------------------
Entradas de las routing tables

Cada routing table podría contener diferentes entradas e información, como direcciones IPv4 o IPv6. Pero los campos principales de todas las routing tables permanecen iguales
Las siguientes son las principales entradas de una routing table:
* Destino: Esta es la dirección IP del destino final del paquete
* Máscara de subred
* Gateway: Este es el próximo salto, o la dirección IP del dispositivo vecino al cual el paquete es enviado
* Interfaz: Los routers usan típicamente interfaces de Ethernet para conectarse con otros dispositivos en la misma red, como eth0 o eth1, e interfaces seriales para conectarse a WANs de afuera. La routing table lista la interfaz de red de entrada, también conocida como interfaz saliente, que el dispositivo debería usar al enviar el paquete al próximo salto
* Métrica: Esta entrada asigna un valor a cada ruta disponible a una red específica. El valor asegura que el router pueda elegir el camino más efectivo. En algunos casos, la métrica es el número de routers que un paquete de datos debe cruzar antes de llegar a la dirección destino. Si existen múltiples rutas a la misma red destino, el camino con la métrica más baja tiene precedencia
* Rutas: esto incluye subredes directamente conectadas, subredes indirectas que no están conectadas al dispositivo pero pueden ser accedidas a través de uno o más saltos, y rutas por defecto para usar ciertos tipos de tráfico cuando falta información

¿Cómo funciona el enrutamiento en redes? 

Un paquete de red debe dar varios pasos para alcanzar su destino:

1. Una computadora envía un paquete a un router: Similar a las direcciones en un paquete postal, un dispositivo que envía (como una computadora) conecta direcciones IP a paquetes de datos y los envía a un router. Esto ayuda al router a determinar las mejores rutas para transportar los paquetes a su destino. Una computadora se conecta típicamente a una LAN para enviar paquetes mientras el router puede enviar paquetes entre diferentes LANs y WANs

2. El router recibe el paquete: una vez el router recibe el paquete, lo analiza contra sus routing tables internas para determinar el camino más eficiente por el cual enviar el paquete. El objetivo del router es enviar el paquete al router más cercano al destino final

3. El router enruta el paquete: es poco probable que el router inicial enviará el paquete directamente a destino. Mira a la routing table para enviar al paquete al próximo salto. La routing table mantiene la cuenta de saltos baja al proveer al router con la ruta más efectiva. La cuenta final de saltos es la cantidad de veces que un paquete va de un router al otro hasta que llega a destino

4. El proceso se repite: en el próximo salto, otro router toma el mando y repite el mismo proceso de determinar a donde enviar el paquete mirando a sus routing tables internas. Este proceso se repite varias veces antes de que el paquete llegue a destino. El proceso de enrutamiento podría sonar largo, pero es extremadamente rápido debido a los protocolos de enrutamiento involucrados

5. El paquete llega a destino: Una vez un paquete ha llegado a un router que reside en la misma red que la dirección IP destino, es enrutado directamente al dispositivo o servidor al cual fue intencionado
